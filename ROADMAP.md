# WUI: состояние и план развития

Актуализировано 16 ноября 2026 года для **1.5.261116**. Ниже отдельно указаны
реализованные возможности и следующие задачи. Завершённый пункт означает наличие
кода и описанной проверки, а не поддержку всех ОС, устройств и desktop environment.

### Обновление до 1.5

Изменилось внутреннее устройство `timer` и `scroll`. Нужно **полностью пересобрать
WUI и все использующие её приложения с заголовками из той же ревизии**. Смешивание
старых заголовков с новой статической библиотекой приводит к несовместимому layout
объектов и повреждению памяти. Таймер Windows создаётся на потоке с message loop;
Linux callbacks выполняются на X11 UI-потоке. Media callbacks, напротив, выполняются
на потоках устройств и не должны напрямую менять UI.

## Принципы и дальнейшее развитие

Сохраняем C++17, небольшой API и документированные системные зависимости.
Изменения публичного контракта и ABI описываем в changelog; форматирование отделяем
от исправлений. Проверяем владение, подписки, разрешённые потоки вызова, координаты
и обработку ошибок на реальных приложениях — в том числе VideoGrace и Decima-8.
Показатели размера и отзывчивости публикуем только вместе с методикой измерения.

Следующие инженерные разборы: перенос VideoGrace на macOS, работа UI-потока,
отзывчивость длинных списков и подключение media API. Для роста проекта нужны
внешние пилоты и понятные задачи для первого вклада, а не только новые платформы.

Нативный Wayland, ускоренный рендеринг и интеграция с внешними event loop зависят от
подтверждённых сценариев. Mobile-порты, визуальный дизайнер, множество биндингов
и вступление в Boost не входят в ближайшие обязательства. Ориентир «Boost.UI»
сохраняется как требование к понятному C++ API и сопровождению.

Пересматриваем этот документ после каждого релиза, сохраняя один основной поток
разработки и небольшие независимые исправления и обновления документации.
