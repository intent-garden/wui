# Устройства macOS: экспериментальный API

Включите `WUI_ENABLE_MEDIA=ON` в CMake и линкуйте приложение с `wui`.
Заголовок — `wui/media/devices.hpp`; включённая сборка экспортирует
`WUI_HAS_NATIVE_MEDIA=1`. По умолчанию модуль выключен. Реализаций для
Windows и Linux пока нет.

API перечисляет микрофоны, динамики и камеры с постоянными системными ID,
захватывает микрофон, воспроизводит PCM, получает видео камеры и основного экрана.
Он не включает RTP, кодеки, AEC, AGC и шумоподавление — они остаются в приложении.
Пустой ID выбирает системное устройство по умолчанию.

## Аудио

`audio_stream` использует signed 16-bit interleaved stereo PCM, 48 кГц.
Playback callback заполняет 1920 отсчётов: 960 стереокадров, или 20 мс.
Capture может возвращать короткие блоки: при необходимости приложение собирает
из них блок нужного размера. Перед playback callback буфер очищается.
Каждый поток владеет отдельной AudioQueue; `start_*` сначала останавливает
предыдущий поток. Метод `error()` возвращает описание ошибки запуска.

## Камера и экран

`video_capture::start_camera()` выбирает точное разрешение и согласует целевую
частоту кадров с диапазонами камеры. Выбирается наибольшая доступная частота
не выше запрошенной; если такой нет — наименьшая выше неё. Например, камера
с частотами 30/24/20 FPS запускается на 24 FPS при запросе 25 FPS.
Неподдерживаемое разрешение возвращает ошибку, а не заменяется другим.

Видео передаётся как BGRA сверху вниз со stride: строки могут содержать отступы.
`start_screen()` масштабирует основной экран до запрошенного размера.
Захват экрана использует ScreenCaptureKit и требует **macOS 12.3+**.

## Разрешения, потоки и время жизни

В `Info.plist` нужны `NSCameraUsageDescription` и `NSMicrophoneUsageDescription`.
При ещё не выданном разрешении запуск запрашивает его и возвращает false;
повторите запуск после согласия пользователя. Для экрана нужно системное
разрешение Screen Recording.

Callbacks работают на потоках устройств; переданные буферы действительны только
до возврата из callback. Не бросайте исключения и не меняйте WUI-контролы напрямую:
передавайте действие в UI через `window::emit_event()`.

`stop()` и деструктор синхронно дожидаются callbacks. Не вызывайте их из callback
этого же потока. Запуск, остановку и смену устройств приложение должно
сериализовать на своём управляющем потоке. Уведомления о hotplug и runtime-ошибках
в текущий media API не входят.

## Проверка сборки

```sh
cmake -S . -B build-media -DWUI_ENABLE_MEDIA=ON -DWUI_BUILD_TESTS=ON -DWUI_BUILD_EXAMPLES=OFF
cmake --build build-media --target wui_macos_test wui_macos_media_test
ctest --test-dir build-media -R '^macos_(integration|media)$' --output-on-failure
```

Проверка media перечисляет устройства, проверяет неверные аргументы и тихое
воспроизведение. Она не заменяет ручную проверку захвата, разрешений и hotplug
на целевых устройствах.
